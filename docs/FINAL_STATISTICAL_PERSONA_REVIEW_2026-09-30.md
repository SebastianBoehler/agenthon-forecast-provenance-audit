The current manuscript is a credible, narrow empirical release audit. Its strongest evidence is a wrong financial quantity surviving shared verification and coarse bounds, followed by paired grading of unchanged answers. The proposed MATH500 addition could establish a concrete failure in a pinned public grader and its effect on a bounded saved-answer panel. Exact rational equality, targeted controls, and paired scoring are established techniques; the addition would supply empirical evidence, not a new grading algorithm or demonstrated training harm.

Proceed only with a frozen representation scope, a complete exclusion ledger, extraction controls, and explicit nondecision statuses. Hundreds of variants from a few reference values and three seeds do not establish independent breadth or precise model rankings.

### Selection and reference contract

1. Pin the dataset revision, source hashes, native code revision, parser grammar, control rules, and planned analysis before model-answer access. Process all 500 source cases into a reference-only census with stable IDs and one recorded eligibility decision per case.
2. Call the subset **grammar-eligible scalar rational**, not all rational answers. A rational expression outside the chosen grammar is unsupported; it is not thereby irrational. Reject or separately classify tuples, sets, alternatives, symbolic expressions, percentages, units, and undefined denominators unless their interpretation is explicitly part of the frozen grammar.
3. Parsing a rational gold is not proof that exact equality exhausts the question's answer contract. Separately flag requested approximation, rounding, representation, units, multiple quantities, and domain or set constraints before outputs. Keep ambiguous cases outside claims of uniquely correct final values; retain them in the census ledger.
4. Record whether decimal references are interpreted as exact finite rationals. For example, a finite decimal approximation to a repeating fraction is unequal under exact equality even if a prompt permits it. Do not discover an approximation policy from model outputs and silently change the primary comparator.
5. Fix model-panel selection by a declared hash rule over the eligible cases. Report eligible/excluded counts by available subject and difficulty metadata. Reference-only selection prevents answer-conditioned cherry-picking, but the grammar still selects a particular task mix.

An identity control validates reference admission and interface plumbing. It does not independently establish the reference's mathematical correctness. These references are source targets; no answer-hidden expert adjudication is completed.

### Minimal controls and comparison decomposition

| Control or comparison | What it resolves |
| --- | --- |
| Identity plus exact equivalents in each admitted representation | Whether admission, wrappers, parsing, and canonicalization preserve the same value |
| Targeted unequal sign/fraction/decimal controls plus ordinary unequal integers | Specific collisions and a passing negative control; verify inequality with exact rational arithmetic before native grading |
| Zero, negative values, signed denominators, decimal boundaries, and nonterminating rational values | Degenerate transformations and asymmetric representation behavior |
| Missing, malformed, multiple-answer, and unsupported-format controls | Whether nondecisions are being miscounted as unequal numeric answers |
| Shared extracted scalar, native normalizations versus exact equality | Equality/canonicalization effects with extraction held fixed |
| Full native extraction versus the declared exact pipeline | The combined interface effect, reported separately from equality alone |
| Strict whole-string signed-integer equality on integer-reference cases | A cheap baseline; unsupported noninteger predictions remain unsupported, not silently truncated |

Compute exact values directly from strings or integer numerator/denominator pairs under a bounded numeric grammar with fixed input-length and digit limits; do not pass through binary floating point or execute corpus/model expressions. Certify every equivalent/unequal control in the exact domain, deduplicate numerical and representation collisions, and report controls grouped by source question and transformation. A sign flip of zero is not an unequal negative; transformations can also reproduce another candidate or an unchanged value.

One extraction hazard is already concrete: the pinned extractor prioritizes the last simple boxed expression anywhere before trying nested boxes. In a source-free diagnostic, an earlier simple box containing 7 overrides a later final box containing one-half. The final-only form is accepted, while the same correct final value with the earlier box is rejected. Freeze final-answer precedence; save the native extracted scalar and winning normalization branch. A rejection's fallback branch label is not an exhaustive explanation of all strategies.

Existing [Math-Verify](https://github.com/huggingface/Math-Verify#architecture) separately exposes extraction, expression conversion, and comparison. Cite that established decomposition. A pinned/configured established evaluator is useful if claiming advantages beyond a narrow Fraction control, but its tolerances, extraction policies, and unit handling do not make it an unquestionable oracle.

### Runtime, censoring, and paired model answers

The inspected RecursiveMAS comparator and counting loop have no native per-case timeout. An audit watchdog is an added resource policy. Preserve timeout, exception, malformed, unsupported, generation-cap, stopped, and not-started statuses separately from a completed unequal-value rejection. Declare input limits and time/process budgets before outputs, retain the triggering bytes, and report both all-scheduled coverage and completed comparisons. Do not silently drop the slow or difficult cases.

Generate each scheduled response once and save it before either grader runs. Both graders see identical bytes; there are no regenerated grader arms. Keep prompts and decoding settings constant within a model/task, with targets hidden from model requests. A new output-format instruction changes the study interface and is not reproduction of RecursiveMAS generation.

A practical optional panel is 32 hash-selected eligible MATH cases and 32 financial cases, eight per existing family, with two available local checkpoints and three fixed stochastic seeds: 384 scheduled answers. Reduce this design before freezing if runtime requires it. Prefer grading already saved financial answers first when time is tight; they need no new calls. If collection stops, preserve the full scheduled denominator and unstarted cases.

Three temperature-zero runs with different seed labels are not three independent stochastic replications. Under stochastic decoding, verify the backend applies the seed, pin temperature and sampling settings, and record seeds and output hashes. Duplicate answers can occur legitimately. Fixed seeds support a repeatable finite realization; two or three do not support precise ranking claims. A fixed or declared interleaved execution order and logged device/runtime settings help expose drift without claiming causal model-size effects.

### Decision gates and failure criteria

- Before financial or MATH generation, the exact parser must preserve every admitted identity/equivalent control and distinguish every admitted unequal control. Source/hash, decimal-to-rational, or backend seed failures block the corresponding claim or execution; fix before freeze or disclose a versioned amendment, rather than replacing an unsuccessful run.
- Native positive-control rejection is a result to explain, not a reason to discard that representation. Exact-comparator unsupported output is a coverage outcome, not proof that the model's answer is wrong. A timeout or exception provides no native accept/reject verdict.
- If native/exact decisions agree on all supported natural saved answers, report no observed natural grading consequence on that panel. Manufactured collisions can still establish a current-code defect, but cannot support naturally occurring score inflation or a model ordering change.
- If differences disappear when both rules use the same extracted scalar, the observed effect is extraction-dependent. If signed-integer equality or the existing integer-plus-half-unit financial baseline resolves a failure, present that cheap success; it defeats the need for a new complex grader.
- If the fixed local budget expires, retain completed and unstarted attempts. Do not replace difficult cases, change token budgets per model after outputs, or select the best seed. Report the incomplete panel without treating missing responses as numerical negatives.

The strongest skeptical objection remains that these are obvious normalization mistakes plus an exact-equality repair. A finite reference census and unchanged natural answers can establish practical incidence and consequences; controls alone are chiefly a reproducible bug diagnosis. Main-track significance would still require broader independently selected released endpoints and convincing semantic authority. This bounded iteration should earn the empirical claim it measures, without promising that extra local runs close those gaps.

### Counts, dependence, and claim boundary

Keep these denominators separate: 500 source cases, eligible source questions, distinct reference values, grouped authored controls, distinct model questions, scheduled question/model/seed attempts, returned answers, and completed paired grading decisions. Reusing a value across many questions or making many variants of one value cannot create independent mechanism replications.

For authored controls, show source-question incidence and transformation-specific acceptance with their denominators. Do not pool them into a natural error rate. For model answers, show a paired decision table on supported completed values, alongside extraction coverage and all-scheduled outcomes. A score difference between full pipelines includes their different coverage policies; identify that rather than attributing the entire difference to numerical equality.

Report finite counts and seed-specific paired differences. No independent-row confidence interval estimates prevalence from this census, and no IID bootstrap over all variants is justified. Any later uncertainty analysis needs a named sampling population and unit; repeated answers should at least remain grouped by question. Three seeds give only coarse information about decoding variation. Zero observed errors on admitted controls is bounded verification, not a universal error guarantee.

The defensible added claim is: **a pinned released grader merges particular unequal values, with a measured scoring consequence on this declared case and response panel**. Exact equality certifies agreement with the annotated scalar; source-solution correctness remains unaudited. The eligible panel does not estimate overall 500-case accuracy. It cannot establish published RecursiveMAS score inflation, defective MATH500 labels, broader financial prevalence, correct reasoning, semantic unit correctness, causal training harm, or new mathematical-verification principles.
